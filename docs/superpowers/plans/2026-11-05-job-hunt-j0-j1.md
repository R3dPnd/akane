# Job Hunt J0–J1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** pnd-job-search runs permanently on this Mac, and `akane hunt` turns the user's criteria into a ranked morning-report file of real, linked leads with fit lines and suggestions.

**Architecture:** pnd-job-search (Go + Postgres) is the engine for JSearch postings and the active resume. The hunt logic is a generic package in the runtime (pnd-mcp `integrations/job_search/`) that talks to the app over HTTP and to Claude through `shared.claude_cli.run_claude`. Akane's launcher adds `akane hunt` and `akane jobs-app`, which manages a launchd agent for the app's backend.

**Tech Stack:** Go 1.x (chi, pgx, goose), PostgreSQL 16 (Homebrew), Python 3.12 (requests, PyYAML, pytest), launchd (`plistlib`, `launchctl`).

**Spec:** `docs/superpowers/specs/2026-11-04-akane-job-hunt-design.md` (§4, §5, §6, §7.1–§7.3, §7.5, §8 rows J0–J1, §10).

## Global Constraints

- Three repos, one branch each:
  - `~/Git/r3dpnd/pnd-job-search`: branch `akane-integration` from `main`.
  - `~/Git/r3dpnd/pnd-mcp`: continue on `persona-agnostic`.
  - `~/Git/r3dpnd/akane`: branch `job-hunt-j0-j1` from `phase2-akane-talks`.
  - Bump akane's `runtime` submodule after each pnd-mcp task (fetch from the local clone, as before).
- Push nothing. Akane, pnd-mcp and pnd-job-search changes stay local until the user says otherwise.
- The JSearch key lives only in `~/Git/r3dpnd/pnd-job-search/.env` (gitignored). Never print it, log it, commit it or copy it elsewhere. The user writes `JOBS_API_KEY=` there; tasks only add other lines.
- Every `claude` invocation runs without `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN`. In Python that's `run_claude`; in Go it's the Task 2 guard.
- Personal criteria live in akane's gitignored `config.local.yaml` (`job_hunt:`, `user.location`). Tracked files hold only commented examples.
- Data paths: `<data_dir>/applications/leads.json` and `<data_dir>/applications/reports/YYYY-MM-DD.md`, where `<data_dir>` is `~/.akane` via `shared.persona.data_dir()`.
- Defaults (spec §4/§7.3): `pay_floor_hourly: 25`, `max_leads: 8`, `max_queries: 6`, `run_at: "04:00"`, screen timeout 600 s, gig search timeout 600 s.
- Tests never call the real `claude` CLI, JSearch, or job sites. They inject fakes for `run_claude`, the HTTP client and the link fetcher.
- Homebrew Postgres connects as the macOS user with no password: `DATABASE_URL=postgres://prestonharms@localhost:5432/job_search?sslmode=disable`.

## Review Focus

1. **The JSearch key is missing or still a placeholder.** `akane hunt` should still finish and write a report whose first line says why there are no job-board leads (gig leads can still appear), not crash. Pinned in Task 6.
2. **Claude returns prose or fenced JSON instead of bare JSON** when screening. Parse fenced JSON; if it's unparseable, write the report with the postings unscored and a note, not an empty report. Pinned in Task 5.
3. **The same posting comes back from two queries in one hunt, or again the next night.** It appears once, and never again once it has been reported. Pinned in Tasks 4 and 6.
4. **The app is down when the hunt runs** (e.g. right after a reboot, before launchd starts it). The report says "job search app not reachable", gig leads still come through, and the exit code is still 0. Pinned in Task 6.
5. **A non-hourly salary** (yearly or monthly from JSearch). Convert it to an hourly equivalent before applying the $25 floor (yearly ÷ 2080, monthly ÷ 173.33). A yearly $60k posting must not be dropped as "$60k < $25". Pinned in Task 5.

- Produces (`rules.py`):

  - `def below_pay_floor(salary_min, salary_max, period, floor: float) -> bool`: True only when there's a stated amount (prefer max, else min) whose hourly equivalent is below `floor`.
  - `def check_link(url: str, get: Callable[[str], int]) -> str`:
    - returns `"ok"` for 2xx/3xx;
    - returns `"blocked"` for 401/403/429;
    - returns `"dead"` for 404/410, other 4xx/5xx, or an exception;
    - `get` returns a status code.
  - `def http_status(url: str) -> int`: the real `get` (requests GET, 8 s timeout, a desktop Chrome user agent, redirects allowed, `stream=True`).

  - `@dataclass class Screen`: `keep: bool`, `score: int`, `fit: str`, `suggestion: str`.

Each candidate dict has `key`, `title`, `org`, `pay`, `location`, `remote` and `description` (trimmed to 1,500 characters). The prompt states the §4 criteria verbatim from `criteria["schedule"]`, `pay_floor_hourly`, `exclude` and the location. It asks for a JSON array `[{key, keep, score, fit, suggestion}]`, says `fit` must tie the posting to the resume *and* the schedule in one sentence, and says not to invent facts about the user.
  - `def parse_screen(text: str) -> dict[str, Screen]`: accepts bare JSON or JSON inside a ```` ```json ```` fence; skips malformed items; raises `ValueError` if no JSON array is found.
  - `def gig_prompt(criteria: dict, location: str, resume_summary: str, known_urls: list[str]) -> str`: asks for currently open async gig opportunities (AI code evaluation and training, paid code review, bounties, freelance) matching the criteria, as a JSON array of `{title, org, url, pay, kind: "gig"}`, excluding `known_urls`, real URLs only.
  - `def parse_gigs(text: str) -> list[dict]`: same fence handling; drops items without an `http(s)` url.

  - `@dataclass class HuntResult`: `report_path: Path`, `added: list[Lead]`, `notes: list[str]`.
  - `def build_queries(criteria: dict, cap: int) -> list[tuple[str, str, bool]]`: `(query, location, remote)`. Each `kinds` entry except gig kinds is paired with each location (`"Remote"` → `("…", "", True)`), truncated to `cap`.
  - `def run_hunt(cfg: dict, *, app: JobSearchApp, store: LeadStore, claude: Callable[..., ClaudeResult], get_status: Callable[[str], int], today: str, reports_dir: Path) -> HuntResult`. It:
    1. gathers postings from every query, collecting `JobSearchUnavailable` messages into notes (once each);
    2. drops known keys and duplicates;
    3. runs the gig search (`claude(gig_prompt(...), allowed_tools=["WebSearch", "WebFetch"], timeout=600)`) unless the gig kinds are excluded;

    6. sorts by score and takes `max_leads`;
    7. calls `store.add`;
    8. writes the report.
  - `def render_report(report_date: str, leads: list[Lead], notes: list[str]) -> str`:
    - front matter `---\nreport_date: …\ndelivered_at:\n---`;
    - heading `# Leads for <Weekday Mon D>`;
    - notes as a `> ` block at the top;
    - each lead as `## <n>. <title> — <org>` followed by lines for pay ("pay not listed" if empty), location/remote, `Fit:`, `Suggestion:`, the link (with ` (couldn't verify — site blocks bots)` when blocked), and `[gig]` for gigs;
    - "No new leads tonight." when there are none.
  - A mid-day rerun on the same date **appends** the new leads to the existing report file, continuing the numbers (spec §7.5).
  - `__main__`:
    - `hunt` loads the config (with `PND_CONFIG_PATH`);
    - `job_hunt` comes from config, with Global Constraints defaults;
    - `app = JobSearchApp(cfg["job_search"]["base_url"])`;
    - `store = LeadStore(data_dir()/"applications/leads.json")`;
    - prints the report path and the number of leads;
    - always exits 0 unless the config is unreadable.
